1 · The one-sentence version

The cart page asked the carrier API for a shipping rate once per item, even though most items share the same carrier and zone. The PR asks once per distinct (carrier, zone) pair and reuses the answer. Prices shown are identical.
Before
1,200 ms
200 items → 200 rate lookups
After
70 ms
12 distinct pairs → 12 lookups, same prices
Target

for the cart page. Verified only after deploy.

2 · Concepts you need

Rate key
The values that decide the price: carrier and zone. Same key → same rate.
Default carrier
If an item has no carrier of its own, the shop's default carrier is used.
Surcharge
A per-zone extra fee added after the base rate is found, so it is part of the key.
Memoisation
Remembering a result for a given input so the expensive call is not repeated.

5 · The code change

Before
for item in cart_items:
  rate = carrier_api.rate(item.carrier, item.zone)  # slow
  prices[item.id] = rate + surcharge(item.zone)
After
seen = {}
for item in cart_items:
  key = (item.carrier, item.zone)
  if key not in seen:                                # NEW
    seen[key] = carrier_api.rate(*key)
  prices[item.id] = seen[key] + surcharge(item.zone)
Details worth noticing
  • The key holds both inputs, so same carrier in a different zone is a different rate.
  • The cache lives for one request only, so rates are never stale across requests.
  • Item order is unchanged, so the cart shows the same list.
